PART 2. CFRP LAMINATE AGENTS (session "OpenSeesPy CFRP ply property
generator")
======================================================================

Goal: model large (geometrically nonlinear) deformation of a thin-shell beam
made of a multi-angle CFRP laminate in OpenSeesPy, with the laminate
material defined from ply properties, and check the result.

Four Claude Code subagents were created. They are instruction files in the
repo; each one runs a Python file in "Code for Project/10-23-26 (Tara)".

  Agent (.claude/agents/)        Python file              What it does
  -----------------------------  -----------------------  ------------------
  PlyPropertyGenerator.md        ply_properties.py        one ply -> OpenSees
                                                          materials at an angle
  LayupFromPlyGenerator.md       layup.py                 layup -> LayeredShell
                                                          sections + elements
  ABDFromOpenSeesPyLayup.md      abd_from_opensees.py     ABD measured from the
                                                          OpenSees calls
  TheoreticalABDGenerator.md     theoretical_abd.py       ABD from classical
                                                          lamination theory

Using the agents
- They are project-level agents (.claude/agents/ at the repo root), so any
  NEW Claude Code session opened in ME295_project or a subfolder loads them.
  A session that was already open when an agent file was created does not
  see it; start a new session.
- Ask by name, e.g. "Use LayupFromPlyGenerator for [0/+-45/90]s with
  E1 = 135 GPa, E2 = 10 GPa, nu12 = 0.3, G12 = 5 GPa, t = 0.125 mm".
- The agents hard-code my Python path
  (D:\Users\tvenkata\miniforge3\envs\shells\python.exe). Federico: change that
  line to your own "shells" env, or we make it portable.
- The Python files can also be run directly; each has --help.
- A subagent cannot launch another subagent in Claude Code. So
  LayupFromPlyGenerator does not "call" PlyPropertyGenerator as an agent; it
  runs the same Python code (ply_properties.py) for every ply.

2.1 PlyPropertyGenerator (ply_properties.py)
- Inputs: E1, E2, nu12, G12, ply angle theta (required); nu23, density, tag.
- Transverse isotropy: E3 = E2, G13 = G12, nu13 = nu12,
  G23 = E2 / (2 (1 + nu23)). If nu23 is not given, nu23 = nu12 is assumed and
  a note is printed.
- Angle convention: theta from global x to the fibre, CCW about global +z.
- Outputs: all 3D constants, the rotated stiffness matrices in the global
  frame (6x6 C_bar and 3x3 plane-stress Q_bar), and the OpenSees chain
    ElasticOrthotropic -> PlaneStress -> PlateFromPlaneStress
  plus the element orientation  '-local', cos(theta), sin(theta), 0.
- --check builds it in OpenSees and confirms the shell element's membrane
  stiffness equals t * Q_bar (machine precision at 0, +-45, 90, 30, 17.3 deg).

2.2 LayupFromPlyGenerator (layup.py)
- Inputs: ply angles bottom to top, thicknesses (one or per ply), ply
  constants. Python API also allows a different material per ply.
- Builds one LayeredShell per ply and one ASDShellQ4 per ply on each facet
  (see takeaways 2-4 for why). Model-script usage:
      p = ply_properties(E1, E2, nu12, G12, nu23, rho)
      plies = make_plies([0, 45, -45, 90], [0.125], p)   # bottom to top
      layup = build_layup(plies)
      for quad in quads:
          ele = add_laminate_elements(ele, quad, layup, '-corotational')
- --check compares the OpenSees laminate with CLT; --emit FILE writes the
  exact OpenSees calls for one facet (input for ABDFromOpenSeesPyLayup).

2.3 ABDFromOpenSeesPyLayup (abd_from_opensees.py)
- Input: a file of ops.nDMaterial / ops.section / ops.element calls (from
  layup.py --emit, or pasted). The file is parsed, not executed.
- Imposes the 3 membrane strains and 3 curvatures on a 1 x 1 mm patch and
  gets ABD from work (imposed displacements x reactions), so no OpenSees sign
  conventions are involved. Prints A, B, D; --save writes a CSV.
- Deliberately independent: no CLT, nothing imported from layup.py or
  ply_properties.py (only numpy + openseespy).

2.4 TheoreticalABDGenerator (theoretical_abd.py)
- Same inputs as the ply and layup agents. Classical lamination theory with
  the Tsai-Pagano invariant form of Q_bar. Prints A, B, D; --save writes a
  CSV in the same layout as abd_from_opensees.py.
- Deliberately independent: numpy only, never calls the other agents,
  scripts or OpenSees.

Verification done today
- Single brick element: ElasticOrthotropic gives the right E1, E2, E3 and all
  six Poisson's ratios.
- Ply rotation: OpenSees membrane stiffness = t * Q_bar to ~1e-16.
- Laminate ABD, OpenSees vs CLT, for [0/45/-45/90], [0/+-45/90]s,
  [0/90/-30] (unequal thicknesses), single ply:
  A and B agree to ~1e-15; D within ~0.4% (see takeaway 5).
- Large deflection (cantilever strip, corotational, 20 x 2 mesh): per-ply
  elements vs an independent single-element model agree to ~1e-14 for
  [0/90]s, [0/90/0/90] and [30]4 (tip deflection up to ~60% of L, tip
  rotation ~66 deg, with bend-twist coupling).
- ABD agent catches a flipped ply angle and plies out of order (ABD changes
  27-80%).
- Hand check of CLT: single 0-deg ply, t = 0.2 mm: A11 = Q11 t = 27181.2 N/mm,
  D11 = Q11 t^3/12 = 90.604 N mm. Matches.

3.2 Four symmetric 4-ply layups (54 micron plies)
- Material: E1 = 139.5 GPa, E2 = 6.101 GPa, G12 = 2.574 GPa, nu12 = 0.2750.
  The given nu21 = 0.0120 was NOT used as an input; nu21 = nu12 E2 / E1 =
  0.0120271 was used so the constants are consistent (matches 0.0120 to the
  given rounding). nu23 = nu12 assumed (G23 = 2392.55 MPa). t = 0.054 mm,
  h = 0.216 mm.
- Layups (given top to bottom; all symmetric, so the order is the same
  bottom to top): L1 [0/90/90/0], L2 [90/0/0/90], L3 [45/0/0/45],
  L4 [-45/90/90/-45].
- Files:
    ply_materials_139GPa.py   0/90/45/-45 materials, tags 11-22 (start at 11
                              to avoid clashing with ply_materials_0_90.py)
    layup_L1_0_90_90_0.py, layup_L2_90_0_0_90.py, layup_L3_45_0_0_45.py,
    layup_L4_m45_90_90_m45.py   one script per layup, 8 layers per ply
- New in these scripts: plies with the SAME angle share one element (its
  LayeredShell holds that angle's material at each of those plies' z
  positions). So each facet has 2 elements (one per distinct angle) instead
  of 4. This is exact with -noeas (element stiffness is linear in section
  stiffness), was checked against one-element-per-ply, and halves the cost.
- Results: B = 0 for all four (symmetric). A agrees to ~1e-16.
    D, OpenSees vs CLT: 0.058% (L1, L2), 0.17% (L3, L4), OpenSees lower.
    L1 vs L2: same A; D11 = 103.49 vs 19.19 N mm (outer plies dominate
      bending).
    L3, L4: non-zero A16/A26 (shear-extension) and D16/D26 (bend-twist),
      because the +-45 plies have no opposite-sign partner.
      L3: A16 = A26 = 3613.73 N/mm, D16 = D26 = 24.59 N mm.
    L4 is L3 rotated by 90 deg: 11 and 22 swap and the 16/26 terms change
      sign.
- The comparison was done by the main session from the saved CSVs, not only
  from the agents' reports.
- The ABD CSVs (abd_clt_L1..L4.csv, abd_opensees_L1..L4.csv, and the [90/0]
  ones) were saved in that session's temporary scratchpad folder, not in the
  project. They are easy to regenerate with --save if needed.


======================================================================
MAJOR TAKEAWAYS (read these before building laminate models)
======================================================================

1. ElasticOrthotropic Poisson's ratios. In
     nDMaterial('ElasticOrthotropic', tag, Ex, Ey, Ez, vxy, vyz, vzx, Gxy, Gyz, Gzx, rho)
   v_ij = -eps_j / eps_i under stress in i. So with x = 1 (fibre):
   vxy = nu12, vyz = nu23, but vzx = nu31 = nu12 * E2 / E1 (~0.02 for CFRP),
   NOT nu13 = 0.3. Checked numerically on a brick element.

2. OpenSees 3.8 cannot rotate a material. There is no nDMaterial that takes
   a ply angle or a full anisotropic stiffness matrix, and ElasticOrthotropic
   cannot hold the coupling terms (Q16, Q26) of an off-axis ply. The ply is
   defined in its own axes and the angle is applied on the element with
   ASDShellQ4 '-local' cos(theta) sin(theta) 0. One element = one orientation
   for ALL its layers.

3. Multi-angle laminates: one ASDShellQ4 per ply on the same four nodes, each
   with its own '-local' angle and its own LayeredShell spanning the full
   laminate in ply order: its ply at the true z position, zero-stiffness
   "void" layers (ElasticIsotropic, E = 0) for the other plies. Their
   stiffnesses add to the exact laminate, including B and the 16/26
   couplings, and with -corotational they share the same kinematics.
   Cost: n_plies elements per facet.

4. -noeas is required for takeaway 3, and it costs mesh accuracy.
   ASDShellQ4's enhanced assumed strain (EAS) modes are condensed out per
   element, which does not add up across the per-ply elements (with EAS
   they were 2% off a single laminate element on a 20 x 2 mesh). With -noeas
   they match to ~1e-14. But without EAS the element is stiffer on coarse
   meshes: for [30]4 at large load the tip deflection was 5.1% below the EAS
   element at 20 x 2 and 2.1% below at 40 x 4 (80 x 8 did not converge with
   my solver settings). => Always do a mesh convergence study.

5. LayeredShell integrates each layer at its mid-plane (one point per layer;
   Federico found the same on 10/22). A ply modelled as one layer misses its
   own Q t^3/12 bending term: D error ~ 1 / (number of layers)^2 (11% with
   3 layers, 1.6% with 8). layup.py splits each ply into sublayers so there
   are at least 15 layers through the thickness (D within ~0.5%); --n-sub
   raises it. So OpenSees D is always slightly BELOW CLT D; A and B are exact.

6. LayeredShell needs at least 3 layers.

7. Layer order: LayeredShell layer 1 is the BOTTOM layer, on the -z side of
   the element normal (n1->n2 x n1->n4). Checked from the sign of B.

8. With every DOF prescribed (patch tests), system('FullGeneral') makes
   Python exit silently (exit code 127). Use system('UmfPack').

9. PlateFromPlaneStress takes one isotropic transverse shear modulus; the
   ply really has G13 and G23. Default used: G13 (= G12). Negligible for
   thin shells; revisit for thick ones.

10. The ABD matrix does not depend on nu13, nu23, nu31 or G23 (plane stress
    only), so an ABD comparison cannot catch errors in those. Takeaway 1 is
    guarded by the brick-element test instead.

11. ABD is a small-strain property: -corotational is dropped when measuring
    it (otherwise geometric terms of the size of the imposed strain appear).

12. Convergence: very tight tolerances (RelativeNormDispIncr 1e-9 or 1e-10)
    stall near the end of large-deflection runs, especially for off-axis
    layups that twist. 1e-6 to 1e-7 worked.

13. When comparing ABDFromOpenSeesPyLayup with TheoreticalABDGenerator,
    expect A and B to agree to round-off and D to agree within ~0.5% (D from
    OpenSees lower, takeaway 5). Anything bigger means a definition error.
    Confirmed on five real layups in Part 3.

14. Plies with the same angle can share one element (Part 3.2), so the
    element count per facet is the number of DISTINCT angles, not plies.
    layup.py itself still makes one element per ply; the L1-L4 scripts do
    the merging. Worth adding to layup.py.

15. Give consistent material constants. A separately rounded nu21 (e.g.
    0.0120) makes the compliance matrix slightly unsymmetric; compute
    nu21 = nu12 E2 / E1 instead, as was done in Part 3.2.

16. Material tags must not clash between files loaded into the same model:
    ply_materials_0_90.py + layup_90_0.py use tags 1-7, and
    ply_materials_139GPa.py uses 11-22.

17. Check the agents' wording, not just their numbers. In Part 3.1 the
    ABDFromOpenSeesPyLayup report described the ElasticOrthotropic arguments
    with the Poisson slots mislabelled (it called 0.0242857 "nu23"). The
    model itself was right (vyz = 0.34, vzx = nu31 = 0.0243); only the
    report's labels were wrong.

18. LayupFromPlyGenerator produced separate per-layup scripts that import
    layup.py and temporarily swap in their own builder for the check. The
    agent's abd_from_opensees.py input therefore had to be recorded from the
    script's calls; layup.py --emit does this for layups built by layup.py.
